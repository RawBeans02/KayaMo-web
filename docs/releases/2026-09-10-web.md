# Website stabilization release — 10 September 2026

This release integrates the pending desktop work and the approved entry redesign. It is not a claim that the entire Personal Growth OS roadmap is complete.

## Included

- Responsive landing/login redesign, transparent companion artwork, clear demo/account separation, recoverable email-link states and resend cooldown.
- Local demo initialization waits for its account-scoped database and an atomically installed, validated food catalog. Failed loading shows a non-destructive retry. The demo no longer claims to be synced.
- Empty/partial server catalog refreshes preserve account-scoped offline foods and servings. Malformed demo downloads can be retried; demo status markup no longer causes hydration errors.
- Demo food logging, task creation/editing, and workouts persist across reloads. Online guest API calls fail before transmitting submitted content.
- Task inspector drafts survive background refreshes. Saved workout results display performed values, not planned targets. Active sessions remain accessible across day boundaries; copying another workout is blocked while a session is active.
- Gym suggestions remain proposals until explicitly accepted. Automatic placement no longer starts in the past, and “what now” no longer invents a 15-minute window or a home location.
- Mus context controls show the four server-enforced domains, not fictitious independent per-screen levels. Failed writes become unverified and require a server read. Legacy local proposal restrictions remain respected.
- Paid web AI routes reserve an atomic, server-only daily request allowance before continuing. The database owns the UTC day; user-editable telemetry is not the enforcement store. Requests, including failed attempts, consume allowance. SDK automatic retries are disabled; timed-out Mus calls are aborted.
- Default request allowance is five per account per UTC day. Server configuration may set WEB_AI_DAILY_REQUEST_LIMIT to an integer from 1 to 100. This is a request allowance, **not exact provider-dollar accounting**; provider/project spending controls are still advisable.
- Gym’s unavailable fallback model was replaced by the configured Mus model, falling back to the API-verified gpt-5.6-luna.
- Restored the shared Taglish default while retaining an explicit English desktop default.

## Deliberate limits and remaining work

- Mobile/Android implementation and publishing are deferred.
- Demo-to-account transfer is not implemented and is explicitly not promised.
- Full Goals/Life/Grove desktop experiences, full mobile-width authenticated layouts, legal/policy content, and comprehensive accessibility/browser coverage remain separate product work.
- Workout pause accounting and unsaved session-note drafts still need durable cross-navigation handling. Task drafts survive polling, not arbitrary selection changes or tab closure.
- Conversation history is stored, but prior turns are not yet sent as model context.
- Exact provider-cost reconciliation and multi-account/global abuse controls remain operational hardening work beyond the new atomic per-account allowance.
- Shared changes were applied as targeted canonical-source fixes with desktop deltas preserved. Older cross-repository divergence remains; a destructive whole-tree sync must not be used to reconcile it.
- Local Docker was unavailable; disposable-database integration was verified in CI. The additive allowance migration was also tested against the configured database with rollback isolation.

## Deployment dependency

supabase/migrations/0020_web_ai_allowance.sql is additive and already applied to the configured project. New environments must apply it and configure a server-only SUPABASE_SERVICE_ROLE_KEY before web AI will work. Missing migration/configuration returns 503 instead of making an unmetered provider call.

The initial broad audits and raw design archives remain local rather than being published into the public repository. No credentials, Android files, or unrelated assistant configuration were included.
